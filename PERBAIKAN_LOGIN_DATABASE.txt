PERBAIKAN LOGIN & DATABASE - JAGOPSI

1. index.html
- Login tidak lagi menunggu api.ipify.org sebagai syarat utama.
- Cek akun/password langsung ke users/{userId}.
- Session cepat disimpan ke user_sessions/{userId} dengan lastIP pending.
- Setelah masuk, IP dan banned IP dicek ringan/asinkron.
- Data akun dicache ke localStorage: pesertaEmail, currentSession, userStatus, userRole, userName.
- Delay 500 ms setelah login dihapus.
- Tombol login diberi mode loading agar tidak kepencet berulang.

2. main.html
- Menu utama langsung memakai cache localStorage agar tidak menunggu database dulu.
- Status akun disegarkan dari Firebase di belakang.
- Jika akun nonaktif, user tetap otomatis dikeluarkan.
- IP/session disinkronkan ulang di belakang tanpa menahan tampilan menu.

3. soal-template-core.js
- Akses paket akademik memakai cache status VIP lebih dulu.
- Status user tetap disegarkan dari Firebase di belakang.
- Live monitor temp_progress tidak lagi update setiap detik terus-menerus.
- Default live monitor dibuat 8 detik sekali, tetapi tetap update saat peserta mulai, pindah nomor, atau memilih jawaban.

Catatan:
- Firebase Realtime Database tetap dipakai.
- Kalau ingin latency lebih rendah lagi untuk Indonesia, opsi terbaik berikutnya adalah membuat Realtime Database baru di region Singapore/asia-southeast1 lalu migrasi data.
